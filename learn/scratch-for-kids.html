Why Scratch is a great first language

Scratch was designed by the MIT Media Lab to be the gentlest possible introduction to programming. Instead of typing syntax, children drag coloured blocks that snap together, so they never get a blank-screen moment. The result is a real, runnable program within a few minutes of opening the editor.

Because Scratch runs entirely in a browser it works on school Chromebooks, Windows laptops and older machines that cannot install software. There is nothing to download and no account is needed just to build and play a project.

The mental models children pick up in Scratch - events, loops, variables and conditionals - are the same ideas that appear in every professional programming language. When a child is ready to move on to Python, JavaScript or GDScript, they already know how programs think. Only the spelling changes.

Scratch also has a large sharing community. Finishing a project and pressing Share gives children a real audience for their work, which is a powerful motivator to keep learning.

What age is Scratch suitable for?

Scratch is officially recommended for ages 8 to 16, but many 6 and 7-year-olds make great progress with an adult alongside them. The drag-and-drop interface means that reading ability is not a strict barrier - children can follow the visual patterns in the block shapes even before they can read every word.

At the other end, teenagers and even adults find Scratch useful for rapid prototyping and game jams. The blocks can build surprisingly complex mechanics when you understand how to use lists, custom blocks and clones.

How to get the most out of these workshops

Open the workshop in one browser tab and Scratch in another. Read one step, do it in Scratch, then read the next. Pausing to run the game after every few steps is the best way to spot a mistake before it hides inside five more blocks.

If something does not work, the most useful question to ask is "what does Scratch think this code should do?" rather than "why is Scratch broken?". Looking at the values your variables hold while the game runs (click the checkbox next to a variable block to show its value on stage) almost always reveals the problem.

When a workshop is finished, change one thing. Increase the fall speed, add an extra platform, give the player two lives instead of one. That act of changing finished code and watching what breaks is how real developers learn.

Frequently asked questions

Is Scratch really free?
Yes. Scratch is free to use, free to create an account for saving and sharing projects, and runs in any modern browser with no downloads. You can build a project without an account - you only need one to save online or share publicly.
Can my child use Scratch on a school Chromebook?
Yes. Scratch runs in the browser and needs no installs or admin rights. It works on Chromebooks, Windows laptops and Macs. If the school has blocked scratch.mit.edu, the workshops here use the JVDesignStudio Arcade Game Maker instead, which also runs in the browser with no account needed.
What do children learn from these Scratch workshops?
Each workshop teaches at least one new coding idea: events, loops, variables, sensing, or lists. By the end of the five main workshops a child understands every concept needed to build any Scratch game they can imagine.
How long does each workshop take?
Most workshops take 30 to 60 minutes at a relaxed pace. The Catch game is the shortest at around 30 minutes. The Platformer takes closer to 90 minutes but can be split across two sessions.
Do I need to know how to code to help my child?
No. The workshops are written so that a child can follow them alone, but many families do them together. The parent or carer does not need any coding knowledge - reading the instructions one step at a time is enough.
