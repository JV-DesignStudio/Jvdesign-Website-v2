# Social Pipeline

Devlog posts are the source for newsletter previews and social queue drafts.

## Source order

- `devlog-data.js` is canonical for public devlog post data.
- `pages/devlog.html` renders the public devlog from that data.
- `pages/newsletter.html` and `newsletter.html` keep a visible devlog path for readers.
- `latest-post.json` is generated by `npm run build:latest` and should match the newest dated post in `devlog-data.js`.

## Draft flow

Run `npm run social:draft` to create queue drafts for the latest five devlog posts. Run `npm run social:check` to verify the latest five already exist without writing files.

Drafts live in `social-posts/queue/`. They are not posted directly from the site build. Each draft includes X or Threads text, an Instagram or Facebook version, and a newsletter blurb.

## Review gate

A social draft is not ready to post until it is represented on the board and has moved through the same gate as site work:

`backlog -> claim -> in_progress -> request-review -> human_review -> done`

Only Josh approves `human_review` to `done`. Posting stays manual after approval, and the posted URL or timestamp should be added to the board evidence.

## Live board edits

Live board evidence can be updated while a social task is in progress:

```bash
node F:/Website/studio-workspace/board-keeper.cjs --update A83 --evidence "Social queue evidence updated"
node F:/Website/studio-workspace/board-keeper.cjs --sync
node F:/Website/studio-workspace/board-keeper.cjs --check
```

The board keeper checks the latest devlog queue files and reports whether they are linked to board review.
