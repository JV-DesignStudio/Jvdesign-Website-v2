Goal for this step

Write a script so your character can run left and right using the arrow keys.

👶 For the child

Time for some CODE! Don't worry, we'll go slowly. We're going to write instructions that tell our character: "when I press the right arrow key, move that way!" It's like programming your own remote control.

👨‍👩‍👧 For the grown-up

Attach a GDScript to the CharacterBody2D root. This step focuses on horizontal movement only. We use Input.get_axis(), a Godot 4 shorthand that returns -1, 0, or +1. move_and_slide() handles all collision response.

??????⭐
Grown-up note: Leave gravity out for now, it's easier for kids to understand movement first, then add gravity in the next step. Breaking it up like this keeps confidence high!

What to do:

  1. 1Click on the Player node in the Scene tree.
  2. 2Click the scroll icon (Attach Script) and click Create.
  3. 3Delete everything in the script and type the code below.
  4. 4Press Ctrl+S to save!
extends CharacterBody2D

const SPEED = 220    # How fast we run

func  _physics_process(delta):
    # left/right movement, get_axis returns -1, 0 or +1
    
    var direction = Input.get_axis("ui_left", "ui_right")
    velocity.x = direction * SPEED

    move_and_slide()

Add Gravity & Jumping
Fall down, then press Space to leap!
Locked
⭐
Goal for this step

Make your character fall down like a real person, and jump when you press the Space bar.

👶 For the child

Right now your character floats like they're in space! Let's add gravity, the invisible pull that brings everything back down. Then we'll give them a jump button. Gravity pulls down a tiny bit every single moment, which is why falling starts slow and gets faster.

👨‍👩‍👧 For the grown-up

Gravity is added to velocity.y each physics frame, multiplied by delta so it's frame-rate independent. Jumping sets velocity.y to a negative value in one go. is_on_floor() is only reliable after move_and_slide() has run at least once, which it has by the second frame.

??????⭐
Grown-up note: The confusing bit for kids is that up is negative in Godot. The top of the screen is y = 0 and numbers grow as you go down, so a jump has to be a minus number. It's worth saying out loud, it comes up in every 2D engine.

What to do:

  1. 1Open your Player script again (double-click it in the FileSystem panel).
  2. 2Add the two new const lines at the top, under SPEED.
  3. 3Add the gravity block and the jump block above the left/right code.
  4. 4Press Ctrl+S to save.
extends CharacterBody2D

const SPEED = 220

const JUMP_FORCE = -400    # minus, because UP is negative!

const GRAVITY = 1200

func  _physics_process(delta):
    # gravity pulls us down a little bit every moment
    
    if  not is_on_floor():
        velocity.y += GRAVITY * delta

    # jump, but only if we are standing on something!
    
    if Input.is_action_just_pressed("ui_accept") and is_on_floor():
        velocity.y = JUMP_FORCE

    var direction = Input.get_axis("ui_left", "ui_right")
    velocity.x = direction * SPEED

    move_and_slide()

Somewhere to land, and platforms to jump between!
Locked
⭐
Goal for this step

Make a Level scene with solid ground and a few floating platforms, then put your player in it.

👶 For the child

Your character needs a world! We're going to build the ground, then some platforms floating in the air to jump up onto, like the bricks in Mario. Each platform is made of two things: a coloured rectangle you can see, and an invisible solid shape you can land on.

👨‍👩‍👧 For the grown-up

Level scene: Node2D root (save as level.tscn). Each platform is a StaticBody2D with a CollisionShape2D (RectangleShape2D) plus a ColorRect for the visual. Duplicate with Ctrl+D. Instance player.tscn and drop it above the ground. Godot will ask you to pick a main scene the first time you press F5, choose level.tscn.

??????⭐
Grown-up note: Make the ColorRect and the RectangleShape2D the same size, or your child will land on invisible air (or fall through something that looks solid). It's the number one source of "why doesn't it work?" in platformers, and a good chance to talk about the difference between what a game looks like and what it does.

What to do:

  1. 1Click Scene ? New Scene, then "Other Node" and choose Node2D. Rename it Level and save it as level.tscn.
  2. 2Add a child StaticBody2D and rename it Ground.
  3. 3Give Ground two children: a ColorRect (make it wide, green, and near the bottom) and a CollisionShape2D with a RectangleShape2D the same size.
  4. 4Click Ground and press Ctrl+D to duplicate it. Drag the copy up and to the right, that's your first floating platform!
  5. 5Duplicate two or three more. Put them at different heights so you have to jump up them like steps.
  6. 6Find player.tscn in the FileSystem panel and drag it into the scene. Move it above the ground on the left.
  7. 7Press F5. Godot will ask which scene to start with, choose level.tscn.

Goal for this step

Add a camera that follows your character so your level can be much wider than the window.

👶 For the child

At the moment your character can run off the edge of the screen and disappear! A camera fixes that. It's like a friend holding a video camera who always keeps you in the middle of the picture. Now your level can be enormous.

👨‍👩‍👧 For the grown-up

A Camera2D added as a child of the Player inherits the parent's transform, so it follows for free with no code at all. Godot 4 makes the first Camera2D in the tree current automatically. Position Smoothing adds a little lag so the camera glides rather than snapping.

What to do:

  4. 4Scroll down to Position Smoothing and tick Enabled.
  5. 5Save with Ctrl+S, go back to level.tscn and stretch your ground much wider.

Add Coins to Collect
Sprinkle treasure all over your level!
Locked
⭐
Goal for this step

Make a coin that vanishes when you touch it and adds one to your score.

👶 For the child

Every platform game needs treasure! A coin is different from a platform: you don't land on it, you walk through it. In Godot that special "notice me but don't block me" node is called an Area2D.

👨‍👩‍👧 For the grown-up

Coin scene: Area2D root + ColorRect + CollisionShape2D (CircleShape2D). Connect the built-in body_entered signal to a script on the coin. The player is added to a group called "player" so the coin can tell the difference between the hero and anything else that wanders in. queue_free() deletes the coin safely at the end of the frame.

??????⭐
Grown-up note: Groups are Godot's simple name-tag system. Adding the Player to a group called "player" means every coin, flag and enemy can ask "was that the hero?" without needing to know where the hero lives in the scene tree.

What to do:

  1. 1Open player.tscn, click the Player node, then open the Node panel (next to the Inspector) and click Groups. Type player and click Add.
  2. 2In the Player script, add the line var score = 0 just under the const lines. Save.
  3. 3Click Scene ? New Scene, choose Area2D, rename it Coin and save it as coin.tscn.
  4. 4Give Coin a small yellow ColorRect and a CollisionShape2D with a CircleShape2D.
  5. 5Click Coin, attach a script, and type the code below.
  6. 6With Coin selected, open the Node panel, double-click body_entered and press Connect.
  7. 7Go back to level.tscn and drag coin.tscn in. Duplicate it with Ctrl+D and scatter coins along your platforms!
extends Area2D

func  _on_body_entered(body):
    # was that the hero, and not a platform or an enemy?
    
    if body.is_in_group("player"):
        body.score += 1
        queue_free()  # the coin disappears!

⭐
Goal for this step

Put a coin counter in the corner of the screen that goes up as you collect.

👶 For the child

Collecting coins is more fun when you can see the number going up! We'll put some text in the corner. It needs to stay stuck to the screen even when the camera moves, so it goes in a special box called a CanvasLayer.

👨‍👩‍👧 For the grown-up

A CanvasLayer draws its children in screen space, ignoring the camera, which is exactly what a HUD needs. The Level script reads player.score each frame. @onready grabs the node references once the scene tree is ready, and str() converts the number into text.

What to do:

  1. 1Open level.tscn. Click the Level root, then add a child CanvasLayer.
  2. 2Add a Label inside the CanvasLayer and rename it ScoreLabel.
  3. 3Drag the Label to the top-left corner. In the Inspector, open Theme Overrides ? Font Sizes and make it nice and big.
  4. 4Click the Level root, attach a script and type the code below.
  5. 5Press Ctrl+S and run it!
extends Node2D

# grab these two nodes when the scene is ready
@onready var player = $Player
@onready var score_label = $CanvasLayer/ScoreLabel

func  _process(delta):
    score_label.text = "Coins: " + str(player.score)
??????⭐
Grown-up note: If you get an error mentioning a null instance, the node names don't match. $Player and $CanvasLayer/ScoreLabel have to be spelled exactly as they appear in the Scene tree, capital letters and all. Great first lesson in why programmers care about spelling!

extends Area2D

func  _on_body_entered(body):

Add an Enemy to Stomp
Bounce on its head, just like Mario!
Locked
⭐
Goal for this step

Make a little enemy that walks back and forth. Land on top to squash it, touch it from the side and you go back to the start.

👶 For the child

Time for a baddie! It marches left and right on its own. Here's the clever bit: the enemy works out how you touched it. If you were falling downwards, you squashed it. If you weren't, it got you, and you go back to the start.

👨‍👩‍👧 For the grown-up

The stomp check is body.velocity.y > 0, meaning the player was moving downwards at the moment of contact. Remember y grows downwards, so falling is positive. We also add a respawn() function to the Player, its first custom function, and a lovely introduction to the idea that objects can be asked to do things.

What to do:

  1. 1Open the Player script and add the start_pos variable and the respawn() function shown below. Save.
  2. 2Click Scene ? New Scene, choose Area2D, rename it Enemy and save it as enemy.tscn.
  3. 3Give Enemy a small red ColorRect and a CollisionShape2D.
  4. 4Attach a script to Enemy, type the enemy code below, then connect its body_entered signal.
  5. 5Drag enemy.tscn into level.tscn and stand it on one of your platforms.
# ADD THESE to your Player script

var start_pos = Vector2.ZERO

func  _ready():
    start_pos = position

func  respawn():
    position = start_pos
    velocity = Vector2.ZERO
# The Enemy script

extends Area2D

const SPEED = 60

var direction = 1

var start_x = 0.0

func  _ready():
    start_x = position.x

func  _process(delta):
    position.x += direction * SPEED * delta
    # turn around after walking 80 pixels each way
    
    if position.x > start_x + 80:
        direction = -1
    
    if position.x < start_x - 80:
        direction = 1

func  _on_body_entered(body):
    if body.is_in_group("player"):
        if body.velocity.y > 0:
            # falling downwards, that's a stomp!
            queue_free()
            body.velocity.y = -300    # little bounce
        
        else:
            body.respawn()

Goal for this step

👶 For the child

You have all the pieces now: platforms, coins, a baddie and a flag. This step is the fun one, you're the level designer! Build a journey from the start to the flag. Make some coins easy and some really tricky to reach.

👨‍👩‍👧 For the grown-up

This is the playtesting step, and it's where the real learning lands. Encourage changing one number at a time (GRAVITY, JUMP_FORCE, SPEED) and playing after each change. That change-test-change loop is genuinely how professionals tune game feel.

??????⭐

  4. 4Play the whole level from start to flag. Can you actually finish it?
  5. 5Tune the feel: bigger GRAVITY for a snappier fall, bigger JUMP_FORCE (more negative!) for a floatier jump.
  6. 6Change the colours of everything until it looks like your game.
  7. 7Get a grown-up or a friend to play it, and watch where they get stuck!
