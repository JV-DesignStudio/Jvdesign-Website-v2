🧒 For the Child

Your game already works brilliantly you've got animatronics, a power meter, multiple nights, and a main menu. 👨‍👩‍👧 For the Grown-Up

This session introduces AnimationPlayer for timed effects, AudioStreamPlayer with generated SFX, modulate-based colour animations, and Sprite2D to replace placeholder geometry. 💡

Step 1
Camera Static Flash!
That satisfying TV-flicker when you switch views...
Locked
🎯
Goal

When the player clicks a camera button, briefly flash a white noisy overlay before showing the new camera just like the real FNAF.

🧒 For the Child

Have you noticed in FNAF that when you switch cameras the screen goes a bit fuzzy for a split second? That's called camera static it looks like old TV interference. It makes the camera switching feel REAL instead of just instantly swapping. It's actually super easy to add we just show a white flash for a tiny moment every time someone presses a camera button!

👨‍👩‍👧 For the Grown-Up

Add a full-screen ColorRect named "CamStatic" to the UI CanvasLayer (or a new CanvasLayer above the cameras), initially invisible, color white with ~0.7 alpha. In show_cam(), before switching the visible panel, make CamStatic visible, await a short timer (0.06s), then hide it and reveal the new camera. The two-frame flash is enough to feel like static without being distracting.

💡
In real FNAF the static is a sprite sheet animation with noise. Our version a quick white flash achieves 90% of the feel with 5% of the effort. This is a great lesson in "fake it 'til you make it" game feel!

What to do:

  • 1In main.tscn, add a new ColorRect inside your UI CanvasLayer. Name it CamStatic.
  • 2Set its anchors to fill the full screen (anchor_right = 1, anchor_bottom = 1). Set color to white with alpha 0.7. Set Visible: off.
  • 3Mark it as a scene-unique node: right-click → "Access as Unique Name" (so you can use %CamStatic in the script).
  • 4Update the show_cam() function in main.gd with the code below.
# Updated show_cam() in main.gd:

func show_cam(index: int):
	# Flash the static overlay first
	%CamStatic.visible = true
	await get_tree().create_timer(0.06).timeout
	%CamStatic.visible = false

	# Now swap to the new camera panel
	for i in cam_panels.size():
		cam_panels[i].visible = (i == index)
	current_cam = index

Try it! Click between camera buttons quickly. Does each switch have a brief white flash? It should feel very satisfying. If it's too bright or too long, adjust the color alpha or the timer wait time.

Step 2
Flickering Office Lights!
The lights are... unstable. How unsettling.
Locked
🎯
Goal

Add a random flicker to the office lighting so the environment feels alive and nervous-making.

🧒 For the Child

Ever been in a spooky movie where the lights flicker? It's terrifying! We're going to make the office lights randomly flicker just for a tiny moment, then back to normal. Most of the time nothing happens. But every now and then: flicker. It makes the whole game feel SO much creepier!

👨‍👩‍👧 For the Grown-Up

Add a semi-transparent dark ColorRect ("LightFlicker") covering the full office area, initially invisible. Add a Timer node ("FlickerTimer") with wait_time around 0.2s and autostart on. In the timeout callback, use randf() to trigger a flicker ~5% of the time briefly show the overlay for 0.08s then hide it.

💡
Randomness creates tension. A light that flickers on a predictable schedule feels mechanical. A light that flickers RANDOMLY keeps the player's brain in a constant low-level alert state.

What to do:

  • 1In main.tscn, add a ColorRect as a child of your root NightWatch node. Name it LightFlicker.
  • 2Set it to cover the full office area. Set color to near-black, alpha ~0.85. Set Visible: off.
  • 3Add a Timer node to NightWatch. Name it FlickerTimer. Set Wait Time: 0.2, Autostart: on.
  • 4Mark LightFlicker as a scene-unique node.
  • 5Add the code below to main.gd.
# Add to main.gd connect FlickerTimer.timeout in _ready():

func _ready():
	# ... your existing _ready() code ...
	$FlickerTimer.timeout.connect(_on_flicker_timer)

func _on_flicker_timer():
	if not game_active:
		return
	if randf() < 0.05:  # 5% chance each tick
		%LightFlicker.visible = true
		await get_tree().create_timer(0.08).timeout
		%LightFlicker.visible = false
🕹️
Try it! Watch the office for 20-30 seconds. Does the light occasionally dip and return? Adjust the randf() threshold (try 0.03 for less frequent, 0.1 for more) until it feels right.

Screen Shake on the Jump Scare!
The whole world shakes when they get you...
Locked
🎯
Goal

When an animatronic triggers the jump scare, violently shake the camera for a second before the game over screen appears.

🧒 For the Child

Right now the jump scare just pops up BOOM, it's there. Imagine if the whole screen shook like an earthquake at the same time? We're going to make the camera rattle around really fast for about a second, then show the game over screen. People are going to SCREAM.

👨‍👩‍👧 For the Grown-Up

Add a Camera2D node to main.tscn. In _trigger_jumpscare(), animate the camera's offset using a Tween rapidly oscillate between small random offsets (e.g. ±15px) over ~0.8 seconds, then reset to (0,0). The Tween approach needs no AnimationPlayer and is cleanly self-contained.

💡
Camera shake is one of game feel's most powerful tools. It communicates impact at a physical level. Use it sparingly only for the jump scare so it retains its impact.

What to do:

  • 1In main.tscn, add a Camera2D node as a child of your NightWatch root. Name it MainCamera.
  • 2Mark it as scene-unique: right-click → "Access as Unique Name".
  • 3Replace your existing _trigger_jumpscare() function in main.gd with the version below.
# Replace _trigger_jumpscare() in main.gd:

func _trigger_jumpscare():
	var tween = create_tween()
	var shake_duration = 0.8
	var elapsed = 0.0
	while elapsed < shake_duration:
		var offset = Vector2(randf_range(-15, 15), randf_range(-12, 12))
		tween.tween_property(%MainCamera, "offset", offset, 0.04)
		elapsed += 0.04
	tween.tween_property(%MainCamera, "offset", Vector2.ZERO, 0.05)

	%JumpScare.visible = true
	await get_tree().create_timer(1.8).timeout
	_game_over()
🕹️
Try it! Let an animatronic reach an open door. When the jump scare triggers, does the screen shake violently? The shake should be fast and chaotic not smooth and gentle.

🎯
Goal

Use Pixel Studio to draw your own animatronic sprite and replace the placeholder ColorRect with a Sprite2D.

🧒 For the Child

Those coloured rectangles pretending to be animatronics? It's time to replace them! Open Pixel Studio and draw your own version of Freddy a round brown bear face, glowing eyes, maybe a hat! YOUR art in YOUR game is a thousand times better than a perfect rectangle.

💡

  • 6Optionally hide or delete the old ColorRect.

Real Sound Effects!
Doors creak. Power hums. Freddy lurks.
Locked
🎯
Goal

Use SFX Studio to generate a door creak, a power hum, and a jump scare sting then wire them up in Godot.

🧒 For the Child

A horror game without sound is like a haunted house with the lights on! We're going to add three sounds: a creaking GROAN when you close a door, a low electrical HUM in the background, and a horrible SHRIEK when the jump scare triggers. Make them as spooky as you want!

👨‍👩‍👧 For the Grown-Up

SFX Studio exports WAV files. Add three AudioStreamPlayer nodes: DoorSFX (non-looping), AmbientHum (looping, from _ready), and JumpScareSFX (one-shot). Vary AmbientHum's pitch_scale based on power level to create increasing tension.

💡
Audio is responsible for roughly 50% of emotional impact in games and film. Adding sound to a previously silent game is the single highest-return polish step.

What to do:

  • 1Open SFX Studio. Generate and download three sounds.
  • 2Drag all three WAV files into the Godot FileSystem dock.
  • 3Add three AudioStreamPlayer nodes: DoorSFX, AmbientHum, JumpScareSFX.
  • 4Assign each audio file to its matching node's Stream slot.
  • 5For AmbientHum: tick Autoplay and Loop.
  • 6Add the code below to main.gd.
# Add to main.gd:

func _on_left_door_pressed():
	# ... your existing door code ...
	$DoorSFX.play()

func _on_right_door_pressed():
	# ... your existing door code ...
	$DoorSFX.play()

# Vary hum pitch as power drains:
func _update_power(delta):
	# ... your existing drain code ...
	$AmbientHum.pitch_scale = 1.0 + (1.0 - (power / 100.0)) * 0.4

func _trigger_jumpscare():
	$JumpScareSFX.play()
	$AmbientHum.stop()

Step 6
Low-Power Warning!
The red glow of impending doom...
Locked
🎯
Goal

When power drops below 20%, add a pulsing red tint to the screen and a repeating warning beep.

🧒 For the Child

When power goes below 20%, the whole office starts glowing a scary red colour that pulses in and out. AND a warning beep starts playing. So the player has THREE ways to know power is low the number, the red glow, AND the sound. It's the panic button!

👨‍👩‍👧 For the Grown-Up

Add a full-screen ColorRect ("PowerWarning") with red color alpha 0. When power drops below 20, start a looping Tween on the alpha (0 to 0.18). Also start a BeepTimer. Use a bool power_warning_active to avoid re-triggering every frame.

💡
Redundant feedback the same information delivered through multiple channels simultaneously (visuals + audio + number) is a cornerstone of good game UX.

What to do:

  • 1Add a ColorRect named PowerWarning to your UI CanvasLayer. Red color, alpha 0.
  • 2Add a Timer named BeepTimer. Wait Time: 1.5, Autostart: off.
  • 3Create a short beep sound and add an AudioStreamPlayer named WarnBeep.
  • 4Add the code below to main.gd.
# Add to main.gd:

var power_warning_active = false

func _update_power(delta):
	# ... your existing power drain code ...
	if power < 20.0 and not power_warning_active and not power_drained:
		power_warning_active = true
		_start_power_warning()

func _start_power_warning():
	$BeepTimer.start()
	$BeepTimer.timeout.connect(func(): $WarnBeep.play())
	var tween = create_tween().set_loops()
	tween.tween_property(%PowerWarning, "color:a", 0.18, 0.4)
	tween.tween_property(%PowerWarning, "color:a", 0.0,  0.4)

func _power_out():
	# ... your existing power-out code ...
	$BeepTimer.stop()
	%PowerWarning.color.a = 0.0
🕹️
Try it! Let your power drain to below 20%. Does the screen pulse red? Do you hear the warning beep?

Door Slam Animation!
Make those doors THUD shut.
Locked
🎯
Goal

When a door closes, animate the door block sliding in from the side instead of just appearing instantly.

🧒 For the Child

Real doors MOVE! We're going to make the door block slide in from the edge of the screen, like a big heavy door slamming shut. It takes about 0.15 seconds and it makes the door feel SOLID and HEAVY.

👨‍👩‍👧 For the Grown-Up

Use a Tween to animate the door block ColorRect's offset_right (for left door) from 0 to 120 in 0.15s using EASE_OUT. For right door: animate offset_left from 960 to 840. Duration matters: 0.15s feels snappy, 0.3s feels sluggish.

💡
Animation duration matters enormously. 0.15 seconds feels snappy and responsive. 0.5 seconds would feel like the door is made of foam. Always err on the side of faster for UI feedback.

What to do:

  • 1Update the door functions to animate using a Tween instead of toggling visible.
  • 2For the left door: tween offset_right from 0 to 120 (0.15s).
  • 3For the right door: tween offset_left from 960 to 840 (0.15s).
  • 4Set door blocks to visible = true in the scene.
# Updated door functions in main.gd:

func _on_left_door_pressed():
	left_door_closed = not left_door_closed
	var tween = create_tween().set_ease(Tween.EASE_OUT)
	if left_door_closed:
		tween.tween_property(%LeftDoorBlock, "offset_right", 120.0, 0.15)
		%CloseLeftDoorButton.text = "🚪 Open Left Door"
	else:
		tween.tween_property(%LeftDoorBlock, "offset_right", 0.0, 0.15)
		%CloseLeftDoorButton.text = "🚪 Close Left Door"

func _on_right_door_pressed():
	right_door_closed = not right_door_closed
	var tween = create_tween().set_ease(Tween.EASE_OUT)
	if right_door_closed:
		tween.tween_property(%RightDoorBlock, "offset_left", 840.0, 0.15)
		%CloseRightDoorButton.text = "🚪 Open Right Door"
	else:
		tween.tween_property(%RightDoorBlock, "offset_left", 960.0, 0.15)
		%CloseRightDoorButton.text = "🚪 Close Right Door"

Animated Death Screen!
Going out with a bang (and a slide-in).
Locked
🎯
Goal

Make the game over screen SLIDE in from below and show which animatronic caught you.

🧒 For the Child

Let's make the game-over screen dramatically slide up from the bottom like a curtain falling. And we'll make it say WHO got you "Freddy got you!" or "Bonnie got you!" A dramatic death screen makes losing feel almost... satisfying?

👨‍👩‍👧 For the Grown-Up

Pass the animatronic name into _game_over(). Add a DeathPanel Control that starts 540px below, then Tween offset_top from 540 to 0 over 0.4 seconds. Named consequences increase emotional investment.

💡
Named consequences increase emotional investment. "Game Over" is generic. "Freddy got you because you forgot to check the right door" is a story.

What to do:

  • 1Update _on_animatronic_at_door() to pass the name to _trigger_jumpscare().
  • 2Add a Control named DeathPanel inside GameOverScreen. Set offset_top to 540.
  • 3Update _game_over() with the slide-in animation below.
# Updated functions in main.gd:

var caught_by = "an animatronic"

func _on_animatronic_at_door(side, who = "an animatronic"):
	var door_closed = left_door_closed if side == "left" else right_door_closed
	if door_closed:
		for node in get_tree().get_nodes_in_group("animatronics"):
			if node.get("room") == (3 if side == "left" else 4):
				node.room = 0
				node._update_display()
	else:
		caught_by = who
		_trigger_jumpscare()

func _game_over():
	game_active = false
	%GoLabel.text = "💀 " + caught_by + " got you!"
	%GameOverScreen.visible = true
	var tween = create_tween().set_ease(Tween.EASE_OUT)
	tween.tween_property(%DeathPanel, "offset_top", 0.0, 0.4)

🎨 What Is Polish?

Polish is the difference between a game that works and a game that feels amazing. None of these steps change how the game is played they change how it feels to play it. A camera flash when you switch views. A light flicker that makes your hands sweat. A screen shake that makes the jump scare genuinely terrifying. Small details, huge impact.
