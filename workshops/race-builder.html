Stardust's five moves

Don't just copy it. Own it.

Copying the finished code proves it runs. Explaining and changing it proves you understand it. Work through these five moves.

  1. 1. See it Pip Watch the finished build work before you type anything. Notice one thing it does that you want to keep. Open it
  2. 2. Understand it Lumo Read why the important lines are there before you copy them. If you can say what a line does in your own words, you understand it. Open it
  3. 3. Build it Ember Type or assemble the guided version yourself. Keep the reference solution closed unless a step stops you. Open it
  4. 4. Fix it Echo Break one line on purpose, run it again, and use the error message or preview to find what changed.
  5. 5. Own it Stardust Change one thing the guide never asked for: changing one rule, level or value and testing what happens. If your version runs, it is yours. Open it

Finished? Check your game

Reaching Step 10 is not the same as finishing. Use this checklist before you call your racing game done.

  • The game starts and you can complete a race.
  • Car physics, rivals, laps, boost pads and the finish line all work.
  • At least one choice is yours: speed, handling, rivals, boost or colours.
  • You playtested it and tuned one value until it felt right.
  • You know how to get back to your version.
How to keep it: your tuning is saved in this browser, so you can come back on the same device. Open My Progress to see your work. Clearing browser data removes the save, so write down your final settings or take a screenshot to keep a copy. The full walkthrough code is in the reference pack.

Explore, Complete, Create

Changing a slider is a good start, but writing the code is the real skill. Work through all three stages, then test your version in your own copy of the game.

1. Explore

In Step 3, set the boost multiplier to 1.0 and try a race. Then set it to 3.0. What difference does it make? Can you find a value that feels fair?

2. Complete

This line is broken. Fix it so driving over a boost pad actually speeds up the car.

car.boost = 0;
Show the fix
car.boost = 60;
3. Create

Write code that draws the current lap number on screen inside the game canvas. Use ctx.fillText() and the G.player.lap variable.

Show one possible answer
ctx.fillStyle = '#f5c400';
ctx.font = 'bold 14px monospace';
ctx.fillText('LAP ' + G.player.lap + ' / ' + G.laps, 10, 20);

The reference pack is for reading the steps offline. To try your lap display idea, change the draw code in this page's racer, then press Run.

Make It Yours, Then Load It In

Your racer and the studio tools are one workflow. Make a colour, sprite, sound or logo, download it, then load it into the game below. No installs, no accounts.

Your final mission

Finish with a racer you designed

Work through all five stages. Your finished game must show at least one original design choice that is not in the starting template.

  1. 1. Customise. Draw your own car in Pixel Studio or pick your own colour in Colour Palette, then load it into the racer.
  2. 2. Expand. Sketch a different track layout in Level Designer, then change one track number in the code to match your plan.
  3. 3. Polish. Add your own boost and finish sounds in Audio Studio and a title logo in Game Logo Maker.
  4. 4. Explain. Write one sentence that names the piece of code you changed and why it changed the game.
  5. 5. Share. Save your settings so you can reopen the game, then show your finished racer to someone.
