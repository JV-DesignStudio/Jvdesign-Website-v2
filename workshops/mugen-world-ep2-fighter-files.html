Meet the Files
Episode 2: What Makes a Fighter

Six file types make one fighter. They sound scary until you know what each one does, and then it is just a checklist. This episode is your map of the whole character.

The def File
The boss file
Active
🎯
Goal for this step

Read a def and find the [Files] list.

  • 1The def starts with [Info]: name, author and version.
  • 2Then [Files] lists the other files by name: cmd, cns, sprite, anim, sound and the palette.
  • 3If a name here is wrong, the engine cannot find that file. This is the number one cause of errors.

Sprites (.sff)
The pictures
Locked
🎯
Goal for this step

Know that .sff holds the artwork.

  • 1.sff is a sprite file: every picture the fighter uses.
  • 2Pictures are grouped and numbered (group, image), and the animation file calls them by those numbers.
  • 3You do not have to draw from scratch: many characters start from a base sprite set.

Animations (.air)
Making sprites move
Locked
🎯
Goal for this step

Know that .air turns sprites into movement.

  • 1.air holds animations. Each one lists sprite numbers and how long each is shown.
  • 2An animation is named by a number that the state code calls, like anim = 200.
  • 3The action number is the link between sprites and states.

Commands (.cmd)
Turning buttons into moves
Locked
🎯
Goal for this step

Know that .cmd connects the controller to the fighter.

  • 1.cmd listens to the buttons and joystick.
  • 2Each [Command] gives a name to a motion, like a quarter-circle punch.
  • 3The state code then reacts to those command names.

Goal for this step

Meet the last two files.

  • 1.cns holds constants and states: the fighter stats and what happens in each state.
  • 2.snd holds all the sounds, called by number just like sprites.
  • 3Together these six files are a complete fighter.
